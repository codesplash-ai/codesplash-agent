## Typed outcomes and recovery

Canonical normalized events remain authority. Derive a separate bounded local outcome JSONL cache:
stable hashed operation ids, sequence/timestamp bounds, turn status, elapsed time, tool-category
completion/failure counts, approval outcomes, error/cancellation counts and observed usage deltas.
Never include prompts, answers, reasoning, provider payloads, tool arguments/output, filenames,
error messages or credentials. Unknown tool/decision names map to fixed categories. Monotonic event
cursors deduplicate replay. Retain at most 1,000 turn outcomes; include an explicit retained-range
indicator. An unfinished turn is running while owned, uncertain after interrupted ownership.

Recorder materializes after durable terminal evidence/flush, with a checksummed control cursor.
A crash between cache replacement and cursor commit does not damage canonical events: readers
recompute from those events, and the owned recorder repairs on open/flush. Cache failure is visible
and must not disable conversation recording. No-history uses the same projection in memory, with
no outcome-file writes. Outcome caches never become billing authority.

## Session info, recaps and titles

Shared info includes local/native/storage identity, effective cwd/project, engine/model, current
versus recorded permission/profile/trust, persistence and recovery status, selected branch/epoch,
queue/checkpoint counts and pending recovery, cumulative versus inherited usage and import/fork
provenance. CLI JSON works without TUI/provider calls. Live `/session-info` uses actual runtime
policy and supports explicit copy of bounded sanitized information through the terminal's clipboard.

Deterministic `/recap`, per-turn summary and return-from-away notice use recorded outcomes and make
no provider call. A recap can select outcomes after an explicit sequence cursor. Returning after
five idle minutes offers a local recap without stealing pending approvals or submitting a draft.
`/rename TEXT` records a manual title; `/rename --auto` deterministically refreshes from eligible
visible conversation evidence. CLI has matching info/recap/outcomes/auto-title operations. Native
`--generate` explicitly requests an optional paid recap/title; vendor adapters without a bounded
no-tool generation contract report that limitation and retain deterministic controls.

Generated requests use only bounded sanitized visible text and typed outcomes (no reasoning/tool
bodies), current native model/provider, zero tools, an input/context budget, <=512 output tokens,
<=16 KiB output and a 30-second deadline. Every observed usage is charged through native auxiliary
accounting; an absent usage report is marked unknown. Never automatically schedule paid summaries.
Manual title changes, branch/cwd/model changes and close invalidate older generated results. Title
application compares a dedicated title revision plus selected branch/cwd token, rather than a
control revision that its own accounted usage may legitimately advance.

## Ownership

Replace the independent M4 learner timer with one session-owned maintenance scheduler. Delayed
learning and explicit generated recap/title work share cancellation/settlement. Foreground input,
model/context/head/cwd changes, permission changes and close cancel and settle owned work before
admission; queued work cannot overlap a maintenance writer. Abort/stale results never become memory
candidates or overwrite manual titles. Keep all provider work bounded; no detached autonomous jobs,
remote telemetry or M7 durable scheduler is introduced.
