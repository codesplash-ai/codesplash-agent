# M7 G — teams, coordinator and live dashboard

Binding before G source implementation, after F local acceptance. Private preparation records
local Claude coordinator/swarm backend/permission-sync references and native C/D/E/F ownership.
All O10 capabilities remain required. M8 general TUI polish and M9 remote session servers stay out.

- Version 1 root SessionStateAccess roster, <=8 teams, <=16 named members/team, <=128 KiB.
  Each name is a bounded literal identifier; members specify agent, role and default prompt.
  Journal last dispatch task IDs. Real peer membership and parent edges use D's bounded journal;
  <=16 retained actual identities/team including nested delegates, within A's root task caps.
- Dispatch runs C's agent tool under its original native permission/approval, sandbox, source,
  checkpoint, hook and budget envelope. Internal team/member metadata is captured at admission;
  public agent input cannot select or forge membership. Nested children inherit their team.
  Repeated dispatch resumes the same child only after its task settles, with C identity checks
  and explicit uncertain-execution review. Opening a roster never starts work.
- Root may inspect/control all owned groups. Children can inspect/message/wait/interrupt only
  their own group or address the root. Ungrouped children cannot cross into named teams. Enforce
  in mailbox routing and peer controls, not only the dashboard. Cross-session endpoints are
  root-only. Messages are attributed data and never silently admit a turn; reply and dispatch
  remain separate actions. Definition/permission restrictions still apply to coordinator tools.
- Persist cumulative inclusive child usage at each actual usage delta, retain parent/child edges
  across resume, and project current task status and bounded sanitized output. Parent usage
  includes delegates; do not sum graph nodes for root totals. Root accounting remains authoritative.
- Explicit persisted root coordinator mode selects a team and adds orchestration instructions.
  The native loop filters its model tool catalog and rejects forged non-orchestration calls before
  resolution/hooks/effects. Built-in coordinator child uses the same model-call restriction.
  Native user controls and delegated children retain their existing authority, subject to normal
  approvals; the coordinator restriction grants none. Resume restores mode, never execution.
- In-process dashboard is always the execution-owner view. SDK/native team controls offer create,
  list/dashboard, peek, reply, explicit dispatch, interrupt, delete and coordinator selection.
  Fresh policy is intersected with the live owner for team controls and delegated agent admission.
  Creating teams, dispatching, changing coordinator mode and opening panes require explicit approval.
- TUI /teams and /dashboard show named members plus actual nested graph/status/usage. Select to peek;
  explicit reply/dispatch input and interrupt work through controller APIs, retaining request origin.
  Existing /tasks, output monitor and Ctrl+B continue to use the same root task registry.
- Tmux is an explicit optional presentation backend. At most eight viewer windows on a generated
  private socket/server with -f /dev/null, fixed argv, minimal environment and quoted native viewer
  command. No user's server/window is addressed. Verify socket ownership/inode before later commands;
  close only this owner's panes/server. Availability/failure is explicit; in-process controls remain.
- Pane viewers use a separate authenticated read-only Unix capability, D descriptor ownership and
  inode/mode checks, <=16 connections, <=64 KiB frames, five-second deadlines, and bounded polling.
  Read-only capability rejects sends and mutations. Viewer never opens an SDK session/provider or
  task owner. Finite CLI owner/viewer <=1 hour; close revokes endpoint and drains owned resources.
  Restart restores roster/topology but neither panes nor old process identities.
- Gate strict schema/caps/recovery, cross-team attacks, actual coordinator delegation/catalog/forged
  write denial, known/unknown usage, reply-without-turn, explicit resume, pending approvals and owner
  close, actual isolated tmux on both hosts, stale/read-only endpoints, rendered TUI controls, compiled
  finite team owner/viewer and fresh SDK example. Then freeze full Mac/Linux checks/builds and all
  accumulated release gates. H final cross-feature review and documentation closure follow.
